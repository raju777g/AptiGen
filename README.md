# AptiGen

AptiGen is an AI-powered aptitude mock test platform. Upload an image of aptitude MCQs or your printed/handwritten notes, and AptiGen automatically turns it into a timed mock test you can take right away.

**Live demo:** _https://aptigenai.netlify.app_

**Frontend repository:** _https://github.com/raju777g/AptiGen-Frontend_

**Frontend repository:** _https://github.com/raju777g/AptiGen-Frontend_

## Features

- **Image to mock test:** upload a photo of MCQs or notes and get a timed test generated by AI
- **Authentication:** email and password with email verification, plus Google and GitHub login
- **AG coin wallet:** earn coins on signup and top up through Razorpay (real money involved)
- **Marketplace:** browse and take public tests created by other users
- **Creator royalties:** earn coins when others take your public tests
- **Daily check-in and streak rewards**
- **Referrals:** both the referrer and the new user get coins on a verified signup
- **Skill radar and analytics:** accuracy breakdown by topic (Quant, Logical Reasoning, Verbal)
- **Custom timers and difficulty modes:** speed run or standard pace
- **Accuracy cashback:** get coins back for a perfect score
- **Weekly live contests:** compete on a scheduled test and win coins and badges
- **Notifications**

## Architecture

```
Browser ──► Netlify (React frontend)
               │  proxies /api, /oauth2, /login/oauth2
               ▼
        Spring Boot backend ──► MySQL (Aiven)
               │
               ├─► OCR.space (text extraction)
               ├─► Groq API (MCQ generation)
               ├─► Razorpay (payments + webhooks)
               └─► SMTP (verification emails)
```

The frontend proxies API and OAuth requests to the backend through Netlify, so the browser treats the session cookie as first-party.

### Prerequisites

- Node.js 18 or later
- Java 17 or later
- MySQL 8 (local, or an Aiven MySQL service)
- API keys for Groq, Gemini and OCR.space
- Razorpay test/live keys
- Google and GitHub OAuth app credentials
- A Mailtrap account (or any SMTP provider)

### Backend

```bash
cd backend
```

Create the database:

```sql
CREATE DATABASE aptigen;
```

Set the environment variables below, then run:

```bash
./mvnw spring-boot:run
```

The API starts at `http://localhost:8080`.

| Variable | Purpose |
| --- | --- |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | MySQL connection (use the Aiven service URI and credentials in production) |
| `GROQ_API_KEY` | AI question generation |
| `OCR_SPACE_API_KEY` | Image text extraction |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` | Payments |
| `RAZORPAY_WEBHOOK_SECRET` | Webhook signature verification |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google login |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub login |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD` | Email sending |
| `FRONTEND_URL` | Allowed CORS origin and OAuth redirect target |

Aiven MySQL requires SSL, so the production `DB_URL` should include `ssl-mode=REQUIRED`, for example `jdbc:mysql://<host>:<port>/<db>?ssl-mode=REQUIRED`.

Never commit real keys. Keep them in environment variables or an untracked local config file.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

The app starts at `http://localhost:5173`. In development, point the API proxy at your local backend (`http://localhost:8080`).

### Webhook testing

Razorpay webhooks need a public URL. For local testing, expose the backend with ngrok and set that URL as the webhook endpoint in the Razorpay dashboard.

## Deployment

- **Frontend:** deployed on **Netlify** and redeploys automatically on every push to `main`. `netlify.toml` proxies `/api`, `/oauth2` and `/login/oauth2` to the backend and includes a fallback rule for client-side routing.
- **Backend and database:** deployed on **Aiven**. Environment variables are set in the hosting dashboard, not committed to the repository. The backend's CORS and OAuth redirect settings must allow the deployed frontend URL.
